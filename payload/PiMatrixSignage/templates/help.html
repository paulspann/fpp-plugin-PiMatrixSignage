Getting started

Pi Matrix Signage can run either as an FPP add-on or as the main interface for a dedicated LED-sign controller. In both modes it designs and schedules content, renders the pixel canvas and can manage the panel controller underneath. FPP remains installed for hardware drivers, plugin installation/update and recovery.

How the system fits together

PartPurpose
Pi Matrix SignageCustomer interface for messages, rendering, schedules, panel setup, licensing, updates and diagnostics.
FPP / controller platformSupplies hardware drivers, plugin installation/update and recovery services. It can remain the visible main interface or sit underneath Pi Matrix Signage in appliance mode.

First-time checklist

  1. Fresh installs start with a one-time controller choice: after the initial administrator password is changed, Pi Matrix Signage asks whether the controller should remain an FPP + Pi Matrix Signage add-on or become a Dedicated Pi Matrix Signage appliance. FPP-first remains the safe default. The choice can be changed later under Display setup → Controller & FPP → Controller interface.
  2. Sign in and replace the initial password when prompted.
  3. Open the cogwheel → Display setup, choose the fitted hardware and enter the panel size/layout.
  4. Save Display settings. Pi Matrix Signage applies the matching underlying panel-controller configuration automatically.
  5. Activate the software licence using the licence key supplied for this controller.
  6. Use Testing & commissioning to verify dimensions, panel order, colour order and orientation.
  7. Create a message, show it manually, then add it to a playlist or schedule.
Autosave: form changes are previewed immediately, but content is not permanent until you use the relevant Save button.

Dashboard

The Dashboard shows what the renderer is doing and provides safe, temporary control of the sign.

Live display

  • Live preview mirrors the current LED canvas in the browser. Turning it off does not stop the physical panels.
  • Exact pixels shows the raw canvas; P5 LEDs simulates panel dots; Smooth enlarges the image without the LED mask.
  • Source identifies whether content comes from a schedule, playlist, manual override, conditional rule or emergency.
  • Return to schedule clears a temporary override and immediately restores automatic selection.

Show something now

Select a saved message and an optional duration. A duration of “Until I clear it” holds the override until Return to schedule is used. Timed overrides expire automatically.

Emergency mode

Emergency mode has the highest priority. It overrides manual content, conditions, schedules and the default message until explicitly ended. Configure the emergency message under Schedules before relying on this control.

Next timed schedule

The Dashboard shows the next enabled timed schedule, its content, start time, configured window and a live countdown. This is a timetable preview: manual overrides, Emergency mode and higher-priority conditional rules can still take precedence.

Messages and Designer

A message is a saved scene. It can contain text, cloud text, images, video, shaders, live widgets, icons and shapes arranged on one logical LED canvas.

Message library

Create, search, duplicate, import, export or delete messages from the library. Show now saves the current edit and places it on the display as a manual override.

Quick editor and Designer

The Quick editor is suited to a single text message with an optional image. Designer exposes the full scene and layer system. Switching to Designer converts compatible Quick content into scene layers.

Cloud Text

Add a Cloud Text layer and enter one phrase per line. The layer shuffles the full list for each playback, displays every phrase before beginning another shuffled round, and automatically fits phrases inside the layer boundary. Each phrase receives free random horizontal and vertical positioning across the layer; colliding positions are rejected so visible phrases remain fully visible and never overlap.

  • Appear every controls how often another phrase is introduced.
  • Visible for sets its total lifetime; Fade in and Fade out use portions of that time.
  • Maximum visible controls how many phrases may share the layer. If the requested timing would exceed this limit, appearances are spaced automatically.
  • Gap reserves clear LED pixels between phrases.
  • Choose a font and pixel/smooth rendering, then use one colour or randomly select from a comma-separated colour palette.

Selection, positioning and order

  • Select a layer in the list or preview. Use Ctrl/Cmd-click for multiple selection.
  • Drag to move; use the resize handle or numeric X/Y/W/H controls for exact geometry.
  • Layer order determines which item appears in front. Use Up and Down to change stacking.
  • Group layers to move or duplicate them as one composition.
  • Zones clip assigned layers to a defined region of the canvas.

Timing and transitions

Each scene has a duration and optional entrance/exit transition. Individual layers can have delays, entrance effects, exit timing and effect speed. Text layers can either display multiple typed lines together or show each non-empty line one after another, automatically dividing the layer’s available timeline between them. With sequential split-flap text, the widest line defines one fixed bank of physical character cells: the next line flips in-place from the previous line, unchanged cells stay put, and cells no longer required visibly rotate to blank. Text layers also include controls for fake flips, character stagger and settle order. A board that starts empty remains blank until each character begins its turn; fake flips are reserved for later changes between populated cells. Mechanical departure/airport casing surrounds each glyph with a real cell frame; **Casing padding** controls the LED-pixel air between the character and that frame. The timeline previews when every layer appears. Scene and layer transitions also include LED-native Pixel columns, Pixel rows, centre-out, spiral and Random LEDs alongside dissolve, checkerboard and Venetian blinds.

Templates, components and history

Templates create a complete starting layout. Components store selected layers for reuse. Every meaningful save creates version history; restoring an older version also preserves the current version so the operation is reversible.

Import and export

Portable message packages include the message definition and referenced media. Importing does not require the original controller to have the same upload paths.

Playlists

A playlist plays saved messages in order. Each item can use its message duration or a playlist-specific duration.

  1. Create or select a playlist.
  2. Add messages from the available-content list.
  3. Drag or use ordering controls to establish playback order.
  4. Set item durations and transition behaviour as required.
  5. Save, then use Show now to test the complete loop.

Deleting a playlist does not delete its messages. Editing a message changes its appearance everywhere that message is used.

Schedules, conditions and emergency priority

Normal schedules

A schedule selects a message or playlist for chosen days and times. Overnight periods may cross midnight. When multiple entries match, priority and specificity determine the active target.

Default content

The default message is shown when there is no emergency, manual override, matching conditional rule or matching timed schedule. Without a default, the canvas may be blank.

Conditional rules

Rules can react to live temperature, feels-like temperature, wind, gusts, humidity, weather category or a JSON/API value. “Must remain true for” prevents brief spikes from triggering content. “Minimum hold” prevents flicker near a threshold.

Brightness schedules

Brightness rules change output intensity by time. A temporary Dashboard brightness override takes precedence until automatic control is restored.

Emergency configuration

Select one saved emergency message. It can be activated from the Dashboard, Remote page, API or configured GPIO input. Latching mode remains active until an authorised user clears it.

Test emergency operation: verify the chosen message, physical button wiring and clear procedure before using it operationally.

Display setup and software licence

Display Setup is split into five task-based sub-tabs. Display contains panel layout/output settings; Profiles contains built-in and saved hardware configurations; Testing & commissioning contains panel tests and the Colorlight commissioning workflow; Physical controls contains GPIO inputs; and Controller contains licensing, controller health/repair, Pi Matrix Signage updates, ISSL-certified FPP platform maintenance and safe Raspberry Pi shutdown.

Licence

Live WHMCS licensing binds the licence key to the displayed Device ID. A successful online check stores a signed entitlement containing a normal verification window and a longer offline grace period.

  • Activate / update licence installs or refreshes a key.
  • Check now requests a fresh signed entitlement.
  • Clear local licence removes the local key and entitlement; it does not reissue the licence in WHMCS.
  • Use WHMCS Reissue before transferring a licence to replacement hardware.
  • To buy a licence, request a reissue or get licensing support, visit www.issl.co.uk/support.

After a software update, the application automatically re-authenticates and reports the new installed version. A temporary network failure does not discard a still-valid signed entitlement.

Panel layout

Enter the width and height of one panel, the number of panels across/down, scan rate and whole-display rotation. This defines the logical canvas used by Designer.

Managed panel output: saving Display settings also asks Pi Matrix Signage to apply the corresponding controller configuration. An existing field-tested physical panel mapping is preserved where the panel count still matches. Use Controller → Apply configuration to re-apply it manually after repairs or advanced work.

Panel tests

Open Display setup → Testing & commissioning and use the Panel test card while commissioning or diagnosing the physical display. Grid and Checker reveal panel order or rotation errors; solid red, green, blue and white help identify colour-order, brightness and dead-pixel problems. Each test runs for 30 seconds and then normal playback resumes automatically.

Output and brightness

Pi Matrix Signage uses the controller platform's physical cape detection data to identify a Hanson rPi-MFC. A physically confirmed Hanson board is offered automatically. Colorlight and both Adafruit adapters remain manual choices because they do not expose one reliable common identification mechanism across all revisions. A virtual Hanson configuration does not by itself count as physical hardware. Pi Matrix renders the completed frame and the internal panel-output service drives the selected hardware. Brightness limits the rendered output globally.

Older rPi-MFC boards: an old or unprogrammed board may not expose a usable EEPROM identity and can therefore be treated as not detected. If a known rPi-MFC installation is hidden unexpectedly, contact ISSL Support rather than changing low-level controller wiring blindly.

Adafruit RGB Matrix HAT / Bonnet

For Raspberry Pi 4-class controllers, Pi Matrix Signage configures the internal RGBMatrix driver with the adafruit-hat mapping and one parallel output. Do not use the PWM hardware modification unless the documented GPIO4-to-GPIO18 change is physically present. For 64×64 panels, follow the Adafruit Address-E jumper instructions for the exact board revision. The current direct RGBMatrix driver is not supported on Raspberry Pi 5.

Adafruit Triple Matrix Bonnet

The Triple Matrix Bonnet is Active3-compatible. On Raspberry Pi 4-class controllers Pi Matrix Signage configures the standard RGBMatrix mapping with 3 parallel outputs. Each IDC connector is a separate parallel HUB75 string. Provide the LED panels with a separate correctly-sized 5V power supply/distribution system; the Triple Matrix Bonnet does not provide panel power. The current direct RGBMatrix driver is not supported on Raspberry Pi 5.

Colorlight 5A-75B / 5A-75E

  1. Program the receiver's driver IC, scan rate and cabinet mapping with Colorlight LEDVISION/LEDSetting and save it to the receiver.
  2. Connect the receiver directly to a dedicated Pi Ethernet interface, normally eth1. Do not share that interface with the normal LAN.
  3. Choose Colorlight and the same interface in Display setup, then save. Pi Matrix Signage creates/updates the matching internal ColorLight 5A-75 output and local frame input automatically.
  4. Run the Grid, Checker and colour tests. If brightness is unreliable, check receiver firmware and its saved configuration.
Receiver setup is separate: Pi Matrix Signage manages the Pi/controller side but does not replace Colorlight's receiver-card programming tool.

Commissioning wizard

The wizard detects Ethernet interfaces and labels the normal-LAN/default-route interface so it is not accidentally selected for Colorlight. Its controller test checks that the panel-output service is active and the managed Colorlight output references the chosen interface. Run and visually confirm Grid, Checker, red, green, blue and full-white before marking the sign commissioned. Hardware changes clear the previous pass.

Hardware profiles

Sixteen built-in sample profiles cover common P5/P10 Hanson, Colorlight, Adafruit RGB Matrix HAT/Bonnet and Adafruit Triple Matrix Bonnet arrangements; Hanson samples are only shown when an rPi-MFC is physically detected. The Profiles sub-tab groups the samples by controller and shows the resulting canvas size to make choosing a close starting point easier. They are starting points, not electrical specifications: verify scan rate, driver mapping, layout and colour order against the actual panel. Built-in profiles cannot be deleted. Apply the closest template, make corrections, then save a named site-specific profile after the sign is working. Profiles include the panel description and dimensions, scan, output hardware, receiver/interface where relevant, layout, rotation, colour order and brightness limit. Applying any profile requires commissioning again.

Controller & FPP

Controller interface switches between the safe default FPP + Pi Matrix Signage add-on mode and Pi Matrix Signage appliance mode. Changing the mode only changes which interface opens at the controller's bare IP/hostname; it does not uninstall FPP or Pi Matrix Signage and does not require a reinstall. Existing appliance installations retain their chosen mode during upgrades.

Panel controller configuration & health checks the underlying FPP API/service, local DDP target, DDP input, physical panel-output configuration and the selected interface mode. Configuration drift is shown explicitly. Repair controller configuration restores the managed local DDP path (127.0.0.1:4048, offset 0), re-applies the selected interface mode and regenerates the panel output; Re-apply panel output is available when only the panel mapping needs to be written again.

Controller software checks both Pi Matrix Signage and the underlying FPP controller platform. Pi Matrix updates continue to install through the plugin updater. For FPP itself, each Pi Matrix release contains one explicit ISSL-certified target; Pi Matrix will never offer an arbitrary latest/nightly FPP build or perform a managed downgrade. When the installed FPP is older and the exact certified .fppos image is available for the controller, an Install certified platform update button appears. A full Pi Matrix + FPP backup is created before FPP's own OS upgrader is started, and the controller reboots during the update.

GPIO controls

The A/B/C physical controls use Raspberry Pi GPIO6, GPIO13 and GPIO26. With a Hanson rPI-MFC, use its dedicated CN2/CN3/CN4 input connectors. With Colorlight, wire a dry/voltage-free contact directly between Raspberry Pi physical pins 31/33/37 respectively and a Pi GND pin. Do not connect the switches to the Colorlight receiver and never apply external voltage to a Pi GPIO input. Physical GPIO controls are unavailable with either Adafruit direct-HUB75 adapter because the Adafruit RGBMatrix/Active3 mappings use GPIO6/GPIO13/GPIO26 as panel signals; Pi Matrix Signage disables GPIO monitoring automatically in those modes.

System diagnostics and recovery

Open the cogwheel and choose System diagnostics to see live controller health and the safe automatic-recovery controls.

Live health

The page reports Pi CPU load and temperature, memory and storage, uptime and IP addresses, renderer frame rate and dropped frames, panel-output/DDP state, internet availability and live-widget fetch health.

Automatic recovery

Automatic recovery can restart a stalled LED renderer and restart the panel-output service when it is genuinely inactive. Threshold and cooldown settings prevent repeated recovery loops. Pi Matrix Signage never automatically reboots or powers off the Raspberry Pi.

Manual recovery and history

Use Restart renderer now or Restart panel output service now when diagnosing a live fault. Recovery history records automatic and manual actions and can be cleared when no longer needed.

Engineering access

In FPP-first mode the FPP interface is already the controller home page. In appliance mode, administrators with both Display setup and Users permission can expand Engineering access, confirm their current password and open FPP in a separate tab for advanced support work. Changes made there can conflict with Pi Matrix Signage managed settings, so use it only for diagnostics/support unless instructed otherwise.

System support package

Create this smaller ZIP from System diagnostics when requesting technical help. It contains application and controller-platform versions, diagnostics, recent warnings/errors, the selected hardware profile, commissioning state, network-interface information, safe licence status, a commissioning certificate and sanitised panel-output configuration. The licence key, passwords and recognised secret fields are excluded. The current display preview is optional; review the ZIP before sharing it.

For technical support, email support@issl.co.uk. Describe the issue, what you were doing, the expected and actual result, any repeatable steps and the approximate time of the fault. Attach the generated support-package ZIP and include a screenshot or photo when the problem is visible on the display. Generate the ZIP as soon as practical after the issue and send it without extracting or editing it.

Access: System diagnostics and its System support package use the Display setup permission.

Shaders and live weather

Shaders can fill the scene background or occupy a normal layer. Built-in controls are generated from each shader’s metadata. The built-in low-resolution library includes Water Ripples, Aurora Ribbons, Fire & Embers, LED Marquee Chase, Starfield / Warp Speed, Falling Particles, Radar Sweep, Matrix / Code Rain, Sky Weather, Cars on Road, LED Plasma and Pixel Waves.

Performance controls

  • Fire & Embers provides camp-fire, hot-ember and magic-flame styles.
  • Falling Particles is one efficient engine for Snow, Confetti, Bubbles, Stars and Hearts.
  • Starfield / Warp Speed, Radar Sweep, Matrix / Code Rain and LED Marquee Chase are tuned for physical LED pixels rather than high-resolution detail.
  • Render rate limits frames per second.
  • Time speed slows, freezes, accelerates or reverses shader time.
  • Performance can render at native, half or quarter resolution. Auto starts at the best practical quality and falls back if needed.

Sky Weather

Manual mode provides clear, partly cloudy, overcast, rain, snow and storm scenes with day, sunset and night phases. Cloud/weather speed is independent of the sun or moon. The celestial body can be positioned, kept stationary or moved at its own speed.

Optional live weather

Enable Use live weather, then enter latitude, longitude and refresh interval. Open-Meteo controls condition, day/night, cloud cover, wind and precipitation. At night Pi Matrix Signage calculates the current moon phase locally and renders the correct crescent, quarter, gibbous or full moon behind the cloud layers, with no extra astronomy request. Saved manual values remain the fallback if live data is unavailable.

Uploaded shaders

ISF-style fragment shaders may use TIME, RENDERSIZE and supported input metadata. Rendering occurs in an isolated helper process so a broken or heavy shader cannot block the main LED loop.

Backup and restore

Backups protect the application database, settings, users, licence data and uploaded assets. Create one before major layout changes or hardware maintenance.

Create and download

  1. Open the cogwheel and choose Backup & restore.
  2. Create a new backup and wait for completion.
  3. Download the ZIP and store a copy away from the controller.

Restore

Upload or select a backup, inspect its version and contents, choose the restore options, then confirm. A safety backup is created before replacement where supported. The service may restart.

Do not interrupt a restore. Keep power connected and wait for the interface or service to return before retrying.

Portable content versus full backup

Message, component and playlist exports are for moving selected content. A full backup is for disaster recovery and controller migration.

Users and permissions

Every operator should have an individual account. Permissions hide inaccessible pages and reject unauthorised server requests.

The cogwheel only appears if the current user can access at least one of Display setup/System diagnostics, Backup & restore or Users. Password changes and Sign out remain available in the top bar.

Remote control

The Remote page is a compact operational view for phones and tablets. It can select messages, return to schedule, blank the display, control brightness and operate emergency mode according to the signed-in user’s permissions.

Remote actions affect the same renderer as the main Dashboard; there is no separate playback state.

Updates and maintenance

Pi Matrix Signage checks for approved application and certified controller-platform updates automatically in the background shortly after startup and every six hours. If either is available, the top-of-screen update banner takes you straight to Display setup → Controller & FPP → Controller software. The Check for updates button performs an immediate manual refresh. The normal status polling reads only the cached result, so release checks do not sit on the renderer/UI hot path.

Pi Matrix plugin updates preserve the persistent database/uploads/licensing data and restart only the Pi Matrix service. Existing safety-backup and rollback tools remain available for recovery. Certified FPP platform updates are more substantial: Pi Matrix first creates a full disaster-recovery backup, then invokes FPP's own .fppos upgrader for the exact certified release. The Pi will reboot and can be unavailable for several minutes.

Recommended maintenance routine

  1. Create and download a full backup.
  2. Open Controller software and choose Check for updates.
  3. Install the approved update and wait for Pi Matrix Signage to return.
  4. Confirm licence status, live output and one representative scheduled message.

Safe operating habits

  • Save after editing and test new content with Show now before scheduling it.
  • Keep a downloaded backup away from the Raspberry Pi.
  • Use named user accounts and only the permissions each operator needs.
  • Test emergency controls and panel patterns periodically.
